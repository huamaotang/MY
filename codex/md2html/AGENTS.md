# Repository Guidelines

## Project Structure & Module Organization

This repository contains a small TypeScript CLI for converting Markdown to styled HTML.

- `src/cli.ts` is the executable entry point. It handles argument parsing, default output paths, file I/O, and `--watch`.
- `src/markdown.ts` contains Markdown parsing, inline rendering, HTML escaping, and the HTML document template.
- `dist/` is generated by TypeScript and contains compiled JavaScript, declarations, and source maps. Do not edit it directly.
- `README.md` documents user-facing usage examples. `README.html` is a generated sample output.
- There is currently no dedicated `tests/` directory.

## Build, Test, and Development Commands

- `npm install` installs local dependencies.
- `npm run build` runs `tsc` and emits compiled files to `dist/`.
- `npm run dev -- input.md -o output.html` runs the TypeScript CLI directly with `tsx`.
- `npm start -- input.md -o output.html` runs the compiled CLI from `dist/cli.js`.
- `node dist/cli.js input.md --watch` verifies watch mode after building.

No automated test script is currently defined in `package.json`.

## Coding Style & Naming Conventions

Use TypeScript with ES modules and strict compiler settings. Keep imports explicit and include `.js` extensions for local runtime imports, matching `NodeNext` behavior.

Follow the existing style: two-space indentation, double quotes, semicolons, named functions for main logic, and clear `camelCase` names for variables and functions. Use `PascalCase` for types such as `CliOptions`.

Keep parsing and rendering logic in `src/markdown.ts`; keep CLI behavior in `src/cli.ts`.

## Testing Guidelines

Until a test framework is added, validate changes with:

```bash
npm run build
npm run dev -- sample.md -o sample.html
```

For parser changes, manually cover headings, paragraphs, unordered and ordered lists, links, images, inline code, emphasis, and fenced code blocks. Prefer future tests near the relevant source, using names like `markdown.test.ts` or a top-level `tests/` directory.

## Commit & Pull Request Guidelines

This repository currently has no git commit history, so no project-specific commit convention is established. Use concise, imperative messages such as `Add watch mode debounce` or `Fix markdown link escaping`.

Pull requests should include a short summary, the commands run for verification, and before/after examples when Markdown rendering changes. Include screenshots or generated HTML snippets for visible output changes.
