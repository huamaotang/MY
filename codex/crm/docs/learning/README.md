# 项目导向学习教程

这些教程不是脱离仓库的语言百科，而是帮助初学者在真实 CRM 代码中形成“能读、能改、能测、能发布”的能力。

## 路线

| 教程 | 适合谁 | 学完应能做到 |
| --- | --- | --- |
| [Java](JAVA.md) | 后端初学者、Android 开发者补语言基础 | 追踪 Spring 请求、修改 Service/Mapper、理解鉴权和事务 |
| [Python](PYTHON.md) | 数据采集/任务维护者 | 增加解析规则、做幂等写入、测试并部署 Prefect Flow |
| [iOS](IOS.md) | Swift/SwiftUI 初学者 | 修改 Codable/API/View，真机构建并理解签名发布 |
| [Android](ANDROID.md) | Java Android 初学者 | 修改 Activity/ApiClient/模型，正确处理线程并生成签名包 |

## 学习方法

每个知识点按五步练习：

1. 读“为什么”：理解概念解决的具体问题。
2. 找“在哪里”：用给出的仓库路径定位真实代码。
3. 画“怎样流动”：从输入追到输出，不急着改。
4. 做“小改动”：只修改一个可验证行为。
5. 用命令验收：构建、测试、接口或设备操作证明结果。

学习练习默认只建议在独立分支和本地/测试环境操作。涉及删除、生产数据库、第三方凭据或商店发布的步骤不能作为练习直接执行。

## 推荐顺序

```text
基础语法/平台 -> 读项目入口 -> 跟一次登录请求 -> 跟一次列表请求
-> 修改一个只读字段 -> 补测试 -> 跑构建 -> 做端到端验证
-> 学配置/并发/安全 -> 理解发布与回滚
```

## 完成标准

学习者应能独立回答：

- 这个功能属于哪个项目和模块？
- 请求、Token、数据和错误经过哪些层？
- 变更会影响哪个数据库、客户端和发布步骤？
- 最小测试是什么，怎样证明没有破坏其他模块？
- 故障时先看哪个日志/状态，而不是盲目改代码？
- 哪些密钥、数据和破坏性操作不能提交或直接执行？

掌握以上问题后，再按 [开发手册总览](../manuals/README.md) 进入真实需求。
